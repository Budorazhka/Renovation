# Напоминания, смена пароля и виджеты второго экрана

Закрыто 16.09.2026 (очередь N-25, «мелочи пакетом»). Четыре места ERP, где
экран выглядел рабочим, а данные в нём были вымышленными или никуда не
сохранялись.

## 1. Смена пароля

`POST /api/v1/auth/change-password` — тело `{ currentPassword, newPassword }`,
ответ `{ changed: true, revokedSessions }`.

| Правило | Как сделано |
| --- | --- |
| Нужен вход | Без активной сессии — 401 `AUTH_NO_SESSION` |
| Нужен текущий пароль | Сверяется argon2-хеш, а для перенесённых учётных записей — прежний bcrypt (`legacyPasswordHash`) |
| Новый пароль не равен текущему | 400 `VALIDATION_FAILED` |
| Длина нового пароля | 8…200 символов, проверка в DTO |
| Перебор | `IpRateLimitGuard`, 10 попыток в минуту с адреса |
| Прочие входы закрываются | Все сессии человека, кроме текущей, отзываются; `revokedSessions` показывается в интерфейсе |
| Перенесённая учётная запись | После смены пароля `legacyPasswordHash` удаляется: дальше действует только новый argon2-хеш |

Экран: «Личный кабинет → Безопасность → Сменить пароль». Ошибки различаются:
неверный текущий пароль (401), слишком много попыток (429), прочее — общий
отказ. Выходить и входить заново не нужно.

## 2. Напоминания

Отдельной сущности «напоминание» на сервере нет и не заводилось: напоминание —
это событие календаря типа `reminder`
(`apps/api/src/modules/crm/schemas/calendar-event.schema.ts`). Поэтому
созданное на экране напоминаний видно и в календаре, и в напоминаниях рабочего
стола, а не только в своей вкладке.

| Действие на экране | Запрос |
| --- | --- |
| Список | `GET /api/v1/calendar/events?type=reminder` за окно −60…+180 дней |
| Создать | `POST /api/v1/calendar/events` с `type: 'reminder'`, длительность 15 минут |
| Выполнено / вернуть в работу | `PATCH /api/v1/calendar/events/:id` со `status` и `expectedVersion` |
| Перенести | `PATCH /api/v1/calendar/events/:id/move` |
| Удалить | `DELETE /api/v1/calendar/events/:id` |

Просрочка не хранится: она выводится из срока и статуса
(`apps/erp-web/src/lib/reminders.ts`, 10 тестов). Конфликт версий (409) —
отдельное сообщение «напоминание изменили в другом месте», список
перечитывается; отказ сервера не подменяется молчаливым успехом.

Было: шесть примеров из `data/info-mock.ts`; отметка «выполнено» и добавленное
напоминание жили до перезагрузки страницы.

## 3. Виджеты второго экрана

| Виджет | Было | Стало |
| --- | --- | --- |
| Команда | `INITIAL_LEAD_MANAGERS` из `leads-mock` — выдуманные фамилии, которых не было ни у одного настоящего лида | ростер из реестра команды (`LeadsContext`, id = `positionId`, тот же, что в `lead.managerId`) |
| Объекты | `mockProperties` | реестр объектов организации (`propertyAssetsApi.listAllAssetsWithListings`) — тот же, что на экране «Мои объекты» |
| Качество объектов | доля «качественных» = 18% от списка примеров | считается по заполненности: фото, цена, площадь, город, улица |

Пока данные не пришли, виджет говорит «Загружаем…», при отказе сервера —
«Данные не загрузились», при пустом реестре — «Данных пока нет». Ноль вместо
цифры не показывается.

## 4. Чаты: панель «База знаний»

Панель показывала первые 12 материалов из `lms-mock`: менеджер мог отправить
клиенту материал, которого в компании нет, а заведённые компанией материалы
в панель не попадали. Теперь панель читает материалы LMS организации
(`useLmsLibrary` → `lmsApi`), при отказе показывает причину, при пустой базе —
«В базе знаний пока нет материалов».

Подборки в той же панели разделены: первичка уже с сервера
(`devSelectionsApiV2`), вторичка остаётся в браузере агента — серверный модуль
`selections` хранит только лоты новостроек (`unitId`). Это отдельная работа
N-27, см. [roadmap-2026-09](../roadmap-2026-09.md).
