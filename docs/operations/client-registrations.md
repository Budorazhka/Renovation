# Фиксация клиента у застройщика

Модуль `client-registrations`, очередь N-26, сделано 16.09.2026. Агентство
заявляет, что покупатель пришёл от него, застройщик подтверждает, и на срок
закрепления вознаграждение по этому клиенту принадлежит агентству.

До этого экран «Регистрации» ERP работал на вшитых примерах и localStorage:
заявка не уходила никуда, застройщик её не видел, «активная бронь» жила до
перезагрузки страницы. Панель застройщика читала коллекцию
`development-sales-clients` старой CRM, которой на новой платформе нет.

## Решения владельца 16.09.2026

| Вопрос | Решение |
| --- | --- |
| Кто подтверждает | Застройщик на платформе. Для застройщика вне платформы — ручная отметка менеджером агентства |
| Срок закрепления | Шесть месяцев с момента подтверждения |

## Модель

Коллекция `client_registrations`. Запись принадлежит агентству
(`organizationId`), а читает её и вторая сторона — застройщик
(`developerOrganizationId`). Его организацию сервер выводит из ЖК, клиент её
не передаёт: иначе заявку можно было бы адресовать любой чужой организации.

| Статус | Что значит |
| --- | --- |
| `pending` | заявка подана, ждёт ответа |
| `active` | клиент закреплён за агентством до `reservedUntil` |
| `rejected` | застройщик отказал, причина в `decisionNote` |
| `completed` | сделка состоялась |
| `cancelled` | агентство сняло заявку, клиент сразу свободен |

Истёкшее закрепление отдельным статусом НЕ хранится: `isExpired` считается на
чтении из `reservedUntil` и статуса — тот же принцип, что `isOverdue` у задачи.
Хранить его значило бы держать второй ответ на тот же вопрос.

## Маршруты

| Маршрут | Кто | Что делает |
| --- | --- | --- |
| `GET /client-registrations` | агентство, `client_registration.read` | свой реестр, свежие первыми (до 200) |
| `POST /client-registrations` | агентство, `client_registration.create` | подать заявку; `Idempotency-Key` обязателен |
| `PATCH /client-registrations/:id` | агентство, `client_registration.update` | лот и заметка, CAS по `expectedVersion` |
| `POST /client-registrations/:id/confirm-external` | агентство, `update` | ручная отметка по застройщику вне платформы |
| `POST /client-registrations/:id/complete` | агентство, `update` | сделка состоялась (только из `active`) |
| `POST /client-registrations/:id/cancel` | агентство, `update` | снять заявку (из `pending` и `active`) |
| `GET /client-registrations/incoming` | застройщик, `client_registration.decide` | заявки к своим ЖК |
| `POST /client-registrations/:id/accept` | застройщик, `decide` | подтвердить, закрепление на 6 месяцев |
| `POST /client-registrations/:id/reject` | застройщик, `decide` | отклонить с причиной |

Гранты по ролям: `read/create/update` — owner, director, rop, manager;
`read` — administrator; `decide` — owner, director, rop и роль developer.
У агентства входящие всегда пусты, у застройщика пуст свой реестр: сторона
определяется данными, а не отдельным переключателем.

## Как выбирается ЖК

Каталог витрины адресует комплекс `slug`'ом — идентификатора у публичной
карточки нет. Поэтому заявка принимает либо `developmentId`, либо
`developmentSlug` (сервер сам находит по нему опубликованный ЖК), либо пару
«застройщик + проект» для застройщика вне платформы. Неопубликованный
комплекс отвечает 404: по идентификатору нельзя узнавать о чужих черновиках.

ERP показывает выбор из каталога: город → список опубликованных ЖК с именем
застройщика (`GET /public/developments`).

## Защита от второй заявки на того же клиента

Перед созданием сервер ищет действующую заявку того же телефона в том же ЖК —
по всем агентствам, в этом и состоит смысл фиксации. Телефон сравнивается без
разделителей: «+995 555 12-34-56» и «995555123456» — один человек. Если клиент
занят, ответ 409 `CLIENT_ALREADY_REGISTERED` с датой окончания закрепления, но
БЕЗ названия агентства-конкурента: заявителю нужно знать, что клиент занят и до
какого числа, а не у кого именно.

Снятая или отклонённая заявка не блокирует: клиент освобождается сразу.

## Аудит

`client_registration.create`, `.accept`, `.reject`, `.confirm_external`,
`.complete`, `.cancel` — все в той же транзакции, что и сама запись.

## Что осталось

Повторная заявка после истечения срока закрепления сейчас проходит: истёкшая
`active`-запись не блокирует нового заявителя. Это соответствует смыслу срока,
но напоминания агентству «закрепление заканчивается через неделю» пока нет —
кандидат в следующую очередь.
