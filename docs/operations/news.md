# Лента новостей ERP и рассылка

Блок «Новости» инфо-центра на рабочем столе и страница «Новости» в ERP.
До 15.09.2026 лента состояла из вшитых примеров, а новость из настроек
сохранялась только в браузере автора, и больше её никто не видел.

## Откуда берутся новости

| Источник | Кто публикует | Кто видит | Где |
|---|---|---|---|
| Новость платформы | администратор BAZA с грантом `news.publish` (или super_admin) | сотрудники всех организаций | админка, раздел «Новости» |
| Новость компании | owner, director, developer своей организации | сотрудники этой организации | ERP, «Настройки → Новости и рассылки → Новости» |

Лента сотрудника (`GET /news`) показывает обе ленты вместе, новые первыми,
до 100 записей. Закреплённые новости ERP показывает сверху.

## Что умеет новость

- **Картинка.** Загружается как любое медиа (ADR-008): upload-intent,
  PUT по presigned URL, confirm. Назначение `news_image`, публичный бакет,
  в ленту идёт вариант `detail` без EXIF (пока worker его не построил —
  оригинал). Новость компании берёт картинку своей организации через
  `POST /media/upload-intent`, новость платформы — через
  `POST /admin/news/images/upload-intent`: у неё владелец «платформа»
  (`ownerScope: { type: 'platform' }`). Чужая картинка — 404, не
  подтверждённая или не `news_image` — 400.
- **Правка.** `PUT` заменяет содержимое целиком (не присланные ссылка,
  подпись или картинка снимаются) и требует `expectedVersion` — версию,
  которую видел редактор. Если новость успели изменить, ответ 409
  `VERSION_CONFLICT`, чужая правка не затирается. У изменённой новости
  лента показывает «изменено». Правка повторно не рассылает.
- **Рассылка.** При публикации можно отметить «на почту» и «в Telegram».

## Рассылка

Получатели — все, кто сейчас занимает позицию в организации (для новости
платформы — во всех организациях), кроме самого автора. Дальше по каналам:

| Канал | Кто получит | Условие на сервере |
|---|---|---|
| Почта | сотрудники, у которых логин — адрес почты и не выключено «Присылать новости на почту» | `SMTP_HOST` и `MAIL_FROM` |
| Telegram | сотрудники, которые подключили бота уведомлений и не выключили «Присылать новости в Telegram» | `TELEGRAM_NOTIFY_BOT_TOKEN` и `TELEGRAM_NOTIFY_BOT_USERNAME` |

Отдельного адреса для писем нет намеренно: иначе можно было бы подписать
на рассылку чужой ящик. Канал, не настроенный на сервере, в ERP и админке
недоступен, доставки по нему не ставятся.

Как это работает. API в транзакции публикации создаёт записи
`notification_deliveries` (`pending`, адрес и текст фиксируются на момент
публикации) и событие outbox `NotificationDeliveriesQueued`. Worker
отправляет и переводит каждую доставку в `sent`, `failed` или `skipped`:

- временная ошибка (сеть, 4xx SMTP, 429 Telegram) — событие повторяется,
  уже отправленное второй раз не уходит;
- постоянная (адрес отвергнут сервером 5xx, бот заблокирован) — `failed`;
  заблокированный бот ещё и снимает привязку чата;
- канал выключили между публикацией и отправкой — `skipped`.

Тот, кто публикует, видит сводку у каждой новости: «Почта: отправлено 12
из 14, ошибок 1».

## Бот уведомлений Telegram

Отдельный бот платформы (не боты организаций из «Чатов»). Создаётся в
@BotFather; токен и имя без `@` — в переменные окружения.

Сотрудник подключает его в ERP: «Личный кабинет → Уведомления →
Подключить Telegram». ERP получает ссылку `https://t.me/<бот>?start=<код>`
(код одноразовый, живёт 15 минут, в базе только хеш), человек жмёт «Старт»,
бот связывает чат с его аккаунтом и отвечает «Готово». Один чат — один
человек: повторная привязка того же Telegram к другому аккаунту снимает
прежнюю. `/stop` в боте отключает уведомления.

Бот работает через long polling (`getUpdates`) из worker'а, публичный
адрес ему не нужен. Позиция чтения хранится в `telegram_bot_states`, после
перезапуска бот не перечитывает старые команды. Опрос ведёт один worker:
Telegram не даёт двум процессам читать один бот одновременно.

## API

| Метод | Путь | Право |
|---|---|---|
| GET | `/news` | `news.read` — лента, `canPublish`, `channels`; публикующим — сводка рассылки |
| POST | `/news` | `news.create`, заголовок `Idempotency-Key` |
| PUT | `/news/:newsId` | `news.update`; новость платформы или чужой организации — 404 |
| DELETE | `/news/:newsId` | `news.delete`; новость платформы или чужой организации — 404 |
| GET | `/admin/news` | admin, грант `news.publish` |
| POST | `/admin/news` | admin, грант `news.publish`, заголовок `Idempotency-Key` |
| PUT | `/admin/news/:newsId` | admin, грант `news.publish`; новость компании — 404 |
| DELETE | `/admin/news/:newsId` | admin, грант `news.publish`; новость компании — 404 |
| POST | `/admin/news/images/upload-intent` | admin, грант `news.publish` |
| POST | `/admin/news/images/:assetId/confirm` | admin, грант `news.publish` |
| GET | `/me/notifications` | свои настройки уведомлений |
| PUT | `/me/notifications` | свои настройки уведомлений |
| POST | `/me/notifications/telegram-link` | ссылка привязки своего Telegram; бот не настроен — 409 `NOTIFICATION_CHANNEL_NOT_CONFIGURED` |
| DELETE | `/me/notifications/telegram` | отвязать свой Telegram |

Тело публикации: `title` (до 200), `body` (до 10 000), `category`
(`company`, `market`, `developer`, `regulation`), `pinned`, `linkUrl`
(только http/https с протоколом), `linkLabel` (до 80, без ссылки не
сохраняется), `imageAssetId`, `sendEmail`, `sendTelegram`. Тело правки —
то же без флагов рассылки плюс `expectedVersion`.

## Журнал

Публикация пишет `news.publish` (с отметками рассылки), правка —
`news.update` (до и после), удаление — `news.delete`; resource `news`.
Актор новости компании — identity сотрудника, новости платформы —
аккаунт администратора.

## Настройка окружения

Переменные (пример — `.env.example`; в `compose.runtime.yml` они
пробрасываются в api и worker):

| Переменная | Кому | Зачем |
|---|---|---|
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD` | worker (api — только `SMTP_HOST`) | SMTP-сервер для писем |
| `MAIL_FROM` | api, worker | отправитель, например `BAZA <news@baza.sale>` |
| `TELEGRAM_NOTIFY_BOT_TOKEN` | api, worker | токен бота уведомлений |
| `TELEGRAM_NOTIFY_BOT_USERNAME` | api, worker | имя бота без `@`, из него API строит ссылку привязки |
| `ERP_PUBLIC_URL` | api | ссылка «Открыть в BAZA» в письме и сообщении |

Пустое значение выключает канал.

## После выкладки

Новые гранты ролей (`news.read` всем, `news.create`/`news.update`/
`news.delete` руководителям) у существующих позиций появляются после
доливки `pnpm --filter @baza/api run grants:backfill-defaults`, см.
[default-grants-backfill.md](default-grants-backfill.md).

Грант администратору выдаёт super_admin в админке (раздел «Аккаунты»):
resource `news`, action `publish`, scope `global`.
